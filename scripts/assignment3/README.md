Assignment 3 Scripts
1. Purpose
This directory documents the computational scripts associated with the Assignment 3 evaluation of isiZulu street-name pronunciation.
The scripts support the comparison of researcher-established reference phone sequences with phone hypotheses generated by the adapted Allosaurus recogniser. The evaluation calculates Levenshtein edit distance and phoneme error rate (PER), and summarises substitutions, deletions and insertions.
The broader research methodology is documented in docs/assignment3/methodology.md and in Methodology Part 2 of the research report.
2. Processing Overview
The Assignment 3 evaluation follows these general processing steps:
1.	Identify the selected street names and the reference phone sequences used in the evaluation.
2.	Obtain the corresponding phone hypotheses from the experimental recordings.
3.	Check that each reference sequence and hypothesis are associated with the same street name.
4.	Align the phone sequences and calculate the edit-operation counts.
5.	Calculate street-level and corpus-level Levenshtein distance and PER.
6.	Export the results for analysis and reporting.
The precise execution order depends on the dependencies implemented in the scripts. Consult each script's configuration and command-line options before running it.
3. Script Inventory
The following inventory should be kept consistent with the actual files present in this directory.
Reference-sequence registry
Expected file: build_study_reference_registry.py
Purpose:
•	Maintains information about the selected street names and their reference phone sequences.
•	Records relevant reference metadata and validation status, where implemented.
•	Provides a way to identify the reference version used in an evaluation.
The registry must accurately reflect the reference sequences used for the reported results. A registry entry should not be treated as independently validated simply because it exists.
Phone recognition
Expected file: recognize_study_streets_research_report.py
Purpose:
•	Runs Allosaurus phone recognition on the configured experimental recordings.
•	Uses the selected adapted isiZulu model when specified in the configuration.
•	Produces phone hypotheses and associated output files for subsequent comparison.
The recogniser's output is a hypothesis rather than a verified transcription. Recognition output should therefore be kept distinct from the reference phone sequences.
Reference and hypothesis comparison
Expected file: build_reference_and_per.py
Purpose:
•	Supports phone-notation mapping and sequence comparison, as implemented in the script.
•	Calculates or prepares Levenshtein edit-distance and PER results.
•	Identifies phone tokens that cannot be handled by the configured mapping, where this check is implemented.
Phone-mapping coverage must be checked before the results are treated as final. Unmapped tokens should be reviewed rather than silently omitted.
Final PER calculation
Expected file: calculate_validated_per.py
Purpose:
•	Calculates PER and edit-distance results from the final reference sequences and corresponding phone hypotheses, if this is the script used for the final analysis.
•	Produces the counts and summary values used in the Assignment 3 report.
If the final calculation is implemented in a differently named script, update this inventory to use the actual filename. Do not list a script as part of the final workflow until its existence and role have been confirmed.
4. Evaluation Metrics
The evaluation uses Levenshtein edit distance and phoneme error rate.
Levenshtein edit distance is the minimum number of phone substitutions, deletions and insertions needed to transform one sequence into another.
The corpus-level PER is calculated using the total edit distance divided by the total number of reference phone tokens. It is not calculated by simply averaging the individual street-level percentages.
The calculation rules and interpretation limitations are documented in docs/assignment3/methodology.md.

6. Reproducibility Checks
Before generating or updating the final results, check the following:
•	The reference phone sequences correspond to the correct street names.
•	The reference-sequence version matches the version used for the reported results.
•	The recognition hypotheses correspond to the intended recordings.
•	The phone-token representation is consistent between the reference and hypothesis sequences.
•	Unmapped phone symbols have been reviewed.
•	The PER denominator uses the number of reference phone tokens.
•	The street-level calculations reconcile with the aggregate edit-operation counts.
•	The generated workbook and figures correspond to the same evaluation run.
The final results should be regenerated if the underlying references, hypotheses or calculation rules change.
7. Data Protection
Do not commit private native-speaker recordings, personal information or restricted external datasets to the public repository unless sharing is explicitly permitted.
The scripts may refer to local data paths that are not included in the repository. Document the expected input structure without exposing private data or machine-specific paths.
8. Limitations
The scripts calculate differences between reference phone sequences and recogniser-generated hypotheses. These differences cannot automatically be attributed to Apple Maps alone because the recogniser and reference-sequence quality can also affect the comparison.
The results are based on the selected 33-street evaluation corpus and should not be assumed to represent every isiZulu street name.
For the interpretation of the metrics and their limitations, refer to docs/assignment3/methodology.md.
