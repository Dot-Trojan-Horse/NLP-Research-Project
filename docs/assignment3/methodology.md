Assignment 3: Evaluation Implementation
1. Purpose
This document records the computational procedure used to produce the Assignment 3 phone-level evaluation results for the research project, Error Analysis of isiZulu Street Name Pronunciation in Existing Systems.
The overall research methodology, dataset collection, pronunciation resources, model adaptation and definitions of the evaluation metrics are documented in the research report's Methodology Part 2. This document supplements that methodology by focusing on the implementation and calculation of the Assignment 3 results.
The evaluation compares researcher-established reference phone sequences with phone hypotheses generated by the adapted Allosaurus recogniser from the corresponding experimental recordings.
2. Evaluation Inputs
The evaluation uses the selected corpus of 33 isiZulu street names, comprising 191 native-speaker recordings and 33 Apple Maps recordings, for a total of 224 experimental recordings.
The computational comparison requires two phone sequences for each evaluated street name:
	Reference sequence: the phone sequence established and checked by the researcher using the available linguistic evidence and pronunciation resources.
	Phone hypothesis: the sequence generated by the adapted Allosaurus recogniser from the corresponding recording.
The reference sequence and hypothesis must correspond to the same street name before the comparison is calculated.
The larger pool of approximately 1,031 curated street names is supporting material for the wider research project. It is not the completed evaluation corpus reported here.
3. Phone Sequence Comparison
Reference and hypothesis sequences are represented as whitespace-separated phone tokens. Each space-delimited token is treated as one unit for the sequence comparison, including multi-character phone symbols represented as a single token.
A dynamic-programming Levenshtein procedure is used to calculate the minimum edit distance between each reference sequence and its corresponding phone hypothesis.
The alignment records three types of operations:
	Substitution: a reference phone is aligned with a different phone in the hypothesis.
	Deletion: a reference phone has no corresponding phone in the hypothesis.
	Insertion: a hypothesis phone has no corresponding phone in the reference.
Where multiple alignments have the same minimum cost, the implementation uses a deterministic tie-breaking order: diagonal match or substitution first, followed by deletion and then insertion.
This procedure provides consistent edit-operation counts for the street-level calculations.
4. PER Calculation
For each street name, the edit-operation counts are used to calculate phoneme error rate (PER):
PER = \frac{\mathbit{S}\ +\ \mathbit{D}\ +\ \mathbit{I}}{\mathbit{N}} x 100
Here, S, D and I are the numbers of substitutions, deletions and insertions, respectively, and N is the number of phone tokens in the reference sequence.
Street-level PER is calculated using the edit distance and reference length for the individual name.
The corpus-level PER is calculated by summing the edit distances across the evaluated street names and dividing the result by the total number of reference phone tokens:
PERcorpus= Ʃ (S + D + I)Ʃ N x 100
The corpus-level calculation therefore weights each street name according to its reference-sequence length. It is not the arithmetic mean of the individual street-level PER percentages.
The analysis also reports descriptive statistics for the street-level PER values, including the mean, median and range. These statistics provide additional information about variation across the 33 selected names.

7. Interpretation and Limitations
The reported metrics quantify disagreement between the reference phone sequences and the phone hypotheses generated from the audio. They do not independently establish the source of each disagreement.
The reference sequences were established and checked by the researcher rather than through a fully independent reference-transcription process. In addition, Allosaurus may introduce recognition errors when converting the recorded audio into phone hypotheses.
Consequently, the reported PER is an experimental measure of phone-sequence disagreement, not a fully independent measurement of Apple Maps pronunciation accuracy.
The evaluation is also limited to the selected 33 street names. Descriptive comparisons involving street-name length or selected phonological features are exploratory and do not establish causal relationships.
These limitations should be considered when interpreting the results and when selecting examples for further audio and linguistic review.
8. Reproducibility
The associated scripts and supporting documentation should identify the inputs, processing steps and outputs required to reproduce the calculations.
Before the results are described as fully reproducible, the reference-sequence registry, recognition hypotheses and final workbook must be checked for consistency. The reference sequences used to calculate the reported results must be identifiable, and their validation status must be accurately documented.
The scripts, results workbook and figures should remain version-consistent so that a change to the reference sequences or calculation procedure can be traced to the outputs it affects.
Private participant recordings and restricted external datasets must not be committed to the public repository unless sharing is explicitly permitted. Their use may be documented without distributing the underlying audio.
